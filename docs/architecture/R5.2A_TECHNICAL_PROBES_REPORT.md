## Probe 1: OpenCode `ask` permission without `--auto`

- **Hypothesis:** Without `--auto`, OpenCode fails closed (rejects) when an `ask` permission is encountered in non-interactive mode.
- **Environment:** OpenCode v2.2.5, Debian 13, scratch directory with agent definitions.
- **Command:**
  ```bash
  cd /tmp/r52a-probes/probe1
  opencode run --agent ag-002-quality-gatekeeper --format json \
    "Use your shell tool to run: echo PROBE1 > /tmp/r52a-probes/probe1/probe.txt" \
    < /dev/null
  ```
- **Result:** The shell command was rejected with: "This non-interactive run cannot ask the user for permission, so the request was rejected." The file `/tmp/r52a-probes/probe1/probe.txt` was NOT created.
- **Evidence:** Adapter output (tool_use status: "error", metadata: `{"providerCall": {"executed": false}}`); file absence confirmed by `ls`.
- **Limitations:** Tested only with `bash: ask` on AG-002. Did not test `edit: ask` or `write: ask` (but same mechanism applies). Did not test with `deny` permissions.
- **Verdict:** **VERIFIED.** OpenCode fails closed for `ask` permissions in non-interactive mode without `--auto`.

## Probe 2: OpenCode pausing for human approval in non-interactive mode

- **Hypothesis:** OpenCode can pause execution and wait for human approval when an `ask` permission is encountered.
- **Environment:** OpenCode v2.2.5, Debian 13, scratch directory.
- **Command:**
  ```bash
  cd /tmp/r52a-probes/probe1
  opencode run --agent ag-008-backend-developer --format json \
    "Use your shell tool to run: echo PROBE3 > /tmp/r52a-probes/probe1/probe3.txt" \
    < /dev/null
  ```
- **Result:** OpenCode did NOT pause. It rejected the request immediately with: "This non-interactive run cannot ask the user for permission, so the request was rejected." No mechanism to provide approval was available.
- **Evidence:** Agent output text; file absence.
- **Limitations:** Only tested with stdin=/dev/null. Did not test with a TTY or interactive session.
- **Verdict:** **NOT VERIFIED (UNSUPPORTED).** OpenCode does NOT support pausing for human approval in non-interactive mode. It rejects immediately. The approval flow in the specification (§4.4) must be revised to use pre-granted approvals.

## Probe 3: PWD, cwd, and --standalone behavior

- **Hypothesis 3a:** OpenCode resolves working directory from `PWD` environment variable, not from process `cwd`.
- **Hypothesis 3b:** `--standalone` mode honors the requested working directory.

### 3a: PWD wrong, cwd correct (no --auto)

- **Command:**
  ```bash
  cd /tmp/r52a-probes/probe3
  PWD=/tmp/opencode/head opencode run --agent ag-001-project-coordinator --format json \
    "Use your shell tool to run: pwd. Reply with only the path." < /dev/null
  ```
- **Result:** Agent's shell reported `/tmp/opencode/head` (wrong directory, from inherited PWD).
- **Verdict:** **VERIFIED.** PWD inheritance overrides cwd.

### 3b: --standalone mode

- **Command:**
  ```bash
  cd /tmp/r52a-probes/probe3
  opencode run --standalone --agent ag-001-project-coordinator --format json \
    "Use your shell tool to run: pwd. Reply with only the path." < /dev/null
  ```
- **Result:** Agent's shell reported `/tmp/r52a-probes/probe3` (correct directory).
- **Verdict:** **VERIFIED.** `--standalone` honors the requested working directory.

### 3c: PWD explicitly set (workaround)

- **Command:**
  ```bash
  cd /tmp/r52a-probes/probe3
  PWD=/tmp/r52a-probes/probe3 opencode run --agent ag-001-project-coordinator --format json \
    "Use your shell tool to run: pwd. Reply with only the path." < /dev/null
  ```
- **Result:** Agent's shell reported `/tmp/r52a-probes/probe3` (correct directory).
- **Verdict:** **VERIFIED.** Setting `PWD` explicitly corrects the working directory.

**Limitations:** Tested 1-2 times per scenario. 20-consecutive-run verification not performed. The `--standalone` mode starts a private server, which may have different performance characteristics.

## Probe 5: Event format

- **Hypothesis:** OpenCode emits structured JSON events that can be parsed for tool uses, errors, and decisions.
- **Environment:** OpenCode v2.2.5, scratch directory.
- **Command:**
  ```bash
  cd /tmp/r52a-probes/probe4
  opencode run --agent ag-001-project-coordinator --format json \
    "Use your shell tool to run: echo EVENT_PROBE" < /dev/null > events.jsonl
  ```
- **Result:** Event types observed: `step_start`, `step_finish`, `text`, `tool_use`. Error events: `{"type": "error", "error": {"type": "...", "message": "..."}}`.

  Tool use event structure:
  ```json
  {
    "type": "tool_use",
    "part": {
      "type": "tool",
      "tool": "shell",
      "state": {
        "status": "completed" | "error",
        "input": {"command": "..."},
        "output": "..." | null,
        "error": "..." | null,
        "metadata": {"providerCall": {"executed": true/false}, ...},
        "time": {"start": ..., "end": ...}
      }
    }
  }
  ```

  Error event structure (invalid model):
  ```json
  {
    "type": "error",
    "error": {"type": "provider.no-route", "message": "Model unavailable: ..."}
  }
  ```

- **Evidence:** Captured event files (`/tmp/r52a-probes/probe5_events.jsonl`, `probe5_error.jsonl`).
- **Limitations:** Did not capture a delegation event (task tool). Did not test error events from tool execution (only from model unavailability). Did not test `--thinking` output.
- **Verdict:** **PARTIALLY VERIFIED.** Event format is documented for basic runs. Tool use, text, step, and error events are parseable. Delegation and permission events not yet observed.

## Probe 6: Sandbox availability (Debian 13/LXC)

- **Hypothesis:** OS-level sandboxing is available via bubblewrap, Docker, or unshare+bind mounts.
- **Environment:** Debian 13, user namespaces enabled.

### 6a: bubblewrap

- **Command:** `which bwrap bubblewrap`
- **Result:** Not found. Not installed.
- **Verdict:** **NOT AVAILABLE.**

### 6b: Docker/Podman

- **Command:** `which docker podman`
- **Result:** Not found. Not installed.
- **Verdict:** **NOT AVAILABLE.**

### 6c: unshare (user namespace)

- **Command:** `unshare --user /bin/bash -c 'id'`
- **Result:** Works (uid=65534/nobody). User namespaces are available.
- **Verdict:** **AVAILABLE.**

### 6d: bind mount in user namespace (read-only)

- **Command:**
  ```bash
  unshare -Urm /bin/bash -c '
    mount --bind /tmp/r52a-probes /tmp/scratchpad/ro_test
    mount -o remount,ro,bind /tmp/scratchpad/ro_test
    echo "test" > /tmp/scratchpad/ro_test/should_fail 2>&1 && echo "WRITE SUCCEEDED" || echo "WRITE FAILED (read-only enforced)"
  '
  ```
- **Result:** "WRITE FAILED (read-only enforced)" — read-only bind mount works.
- **Verdict:** **VERIFIED.** Read-only bind mounts are possible in user namespaces.

### 6e: network namespace

- **Command:** `unshare --net /bin/bash -c 'echo net'`
- **Result:** "Operation not permitted."
- **Verdict:** **NOT AVAILABLE.** Network namespaces require elevated privileges.

### 6f: mount /proc

- **Command:** `unshare --user --map-root-user --mount-proc /bin/bash -c 'echo proc'`
- **Result:** "mount /proc failed: Operation not permitted."
- **Verdict:** **NOT AVAILABLE.** Cannot mount proc in user namespace.

**Summary:** No bubblewrap or Docker. User namespaces work. Read-only bind mounts work. Network isolation not available. `/proc` mount not available. A sandbox can be built using `unshare -Urm` + bind mounts, but without network isolation or proc mounting.

**Limitations:** The sandbox cannot restrict network egress (no network namespace). The sandbox cannot provide a separate proc filesystem. These limitations must be documented in the specification.

## Consequences for the specification

### 1. Approval flow must be revised (CRITICAL)

The specification (§4.4) assumes OpenCode can pause on `ask` in non-interactive mode. **Probe 2 shows it cannot.** OpenCode rejects immediately. The approval flow must be changed from "pause and wait" to "pre-grant and run":

- Human operator reviews the requested action before the run starts.
- Operator grants the permission via the approval service.
- The run proceeds with the permission granted (recorded in the approval).
- The agent's `ask` permission is temporarily elevated to `allow` for the duration of the run, scoped to the specific action.

**Alternative:** Treat `ask` as `deny` in non-interactive mode. The human must explicitly grant permissions before the run. The run fails if an ungranted `ask` is encountered.

### 2. Sandbox design must use unshare + bind mounts

The specification (§5.2 Layer 4) assumes bubblewrap or Docker. **Probe 6 shows neither is available.** The sandbox must use:

- `unshare -Urm` for user namespace isolation
- `mount --bind` for read-only factory paths
- `mount -o remount,ro,bind` for read-only enforcement
- `mount --bind` for writable worktree path

**Limitation:** No network isolation (network namespaces require elevated privileges). No `/proc` mount. These limitations must be documented.

### 3. Worktree must include configuration

The specification (§5.2 Layer 5) creates worktrees but doesn't account for `opencode.json`. **Probe 7e shows** that a worktree without `opencode.json` lacks the factory's configuration. The worktree materialization must include:
- `.opencode/agents/` (agent definitions)
- `opencode.json` (configuration)
- Verification that materialized files match the normative definitions (hash check)

### 4. Event parsing is feasible

**Probe 5** confirms that OpenCode emits parseable JSON events with tool uses, text, steps, and errors. The adapter can parse these for evidence. The event schema is documented in this report.

### 5. Permission enforcement is fail-closed (VERIFIED)

**Probe 1** confirms that without `--auto`, `ask` permissions are rejected in non-interactive mode. Removing `--auto` from the adapter is sufficient to make `ask` fail closed.

### 6. Agent discovery works from worktree (VERIFIED)

**Probe 4** confirms that 18 agents load from a worktree with `.opencode/agents/`. The discovery mechanism works when agent definitions are present.

### 7. Version pinning

OpenCode v2.2.5 is the tested version. The preflight must check this version and fail on untested versions.

## Impact on specification

The following specification sections must be revised based on probe results:

1. **§4.4 (Approval flow):** Revise from "pause and wait" to "pre-grant and run." OpenCode does not pause.
2. **§5.2 Layer 4 (Sandbox):** Revise from bubblewrap/container to unshare + bind mounts. No network isolation available.
3. **§5.2 Layer 5 (Worktree):** Add materialization of `opencode.json` and `.opencode/agents/`.
4. **§9.2 (Evidence):** Add event schema specification based on probe 5.
5. **§4.3 (Permission profiles):** Add probe for `deny` enforcement (T-SEC-003).
6. **§18 (Risks):** Update sandbox availability and approval mechanism risks.
